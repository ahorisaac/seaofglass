Reading Packets in Wireshark

20 minReading Lab: pending Quiz: pending

Lesson complete — progress saved.

Packets are the security camera footage of the network. Wireshark lets you rewind, filter and read the story.

capture → filter → inspect → follow stream

Wireshark records network traffic and dissects it layer by layer — the OSI model made visible. Two filter types matter: capture filters decide what gets recorded (before storage); display filters decide what you see from an existing capture. Beginners should record broadly, then filter aggressively.

Display filter Shows Use it when…
http Only HTTP requests/responses Hunting cleartext web traffic.
dns Only DNS queries/responses Seeing what names were resolved.
tcp.port == 80 TCP traffic on port 80 Focusing on one service.
ip.addr == 10.10.14.2 Anything to/from that IP Tracking one host.
tcp.flags.syn == 1 SYN packets Spotting scan behaviour.

Ethics & limits

Capture only traffic you own or are authorised to monitor. And remember: TLS turns payload into ciphertext. You can still see IPs, ports, timing and certificate metadata — but not passwords or page content.
