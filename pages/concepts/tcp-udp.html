TCP vs UDP & the Handshake

12 minReading Lab: pending Quiz: pending

Lesson complete — progress saved.

TCP is registered mail: it confirms delivery. UDP is a postcard: fast, fire-and-forget.

TCP: SYN → SYN-ACK → ACK · UDP: just send

TCP Reliable, ordered, connection-oriented

TCP builds a connection first, numbers the bytes, retransmits what is lost, and delivers in order. Use it when correctness matters: web pages, SSH, email, file transfer.

UDP Fast, lightweight, connectionless

UDP sends datagrams without a handshake or delivery guarantee. Use it when speed matters more than perfection: DNS queries, voice/video, games, QUIC.

Step Direction Meaning
SYN Client → Server “I want to start a connection.”
SYN-ACK Server → Client “I hear you, and I agree.”
ACK Client → Server “Confirmed. Let’s talk.”

Why scanners care

A SYN scan sends SYN. If SYN-ACK comes back, the port is open. If RST comes back, it is closed. The scanner never completes the full handshake — hence “half-open” scanning.
